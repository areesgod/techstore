\chapter*{АННОТАЦИЯ}
\addcontentsline{toc}{chapter}{АННОТАЦИЯ}

Настоящая диссертация посвящена проектированию и практической реализации многофункциональной информационной системы электронной торговли «TechStore», ориентированной на рынок Республики Казахстан. В работе рассматриваются архитектурные решения на базе микросервисного подхода с использованием стека технологий React, Vite, TailwindCSS (клиентская часть) и FastAPI, SQLAlchemy, PostgreSQL (серверная часть). Реализованы модули: аутентификация с верификацией почты, каталог товаров с нечётким поиском, корзина покупок с тремя способами оплаты, девятиуровневая программа лояльности, многоязычный интерфейс (русский, казахский, английский), модуль доставки по 55 городам Казахстана, административная панель, портал сотрудников и управление складскими остатками по пяти филиалам. Система развёрнута в облачной инфраструктуре Vercel (фронтенд) и Render (бэкенд + PostgreSQL).

\textbf{Ключевые слова:} информационная система, электронная торговля, REST API, программа лояльности, JWT-аутентификация, многоязычный интерфейс, облачный деплой, FastAPI, React.

\chapter*{ABSTRACT}
\addcontentsline{toc}{chapter}{ABSTRACT}

This dissertation is devoted to the design and practical implementation of a multi-functional e-commerce information system ``TechStore'' targeting the market of the Republic of Kazakhstan. The work examines architectural solutions based on a microservice approach using a technology stack of React, Vite, TailwindCSS (client side) and FastAPI, SQLAlchemy, PostgreSQL (server side). The following modules are implemented: authentication with email verification, product catalog with fuzzy search, shopping cart with three payment methods, a nine-tier loyalty program, multilingual interface (Russian, Kazakh, English), a delivery module covering 55 cities of Kazakhstan, an admin panel, an employee portal, and stock management across five branches. The system is deployed in cloud infrastructure on Vercel (frontend) and Render (backend + PostgreSQL).

\textbf{Keywords:} information system, e-commerce, REST API, loyalty program, JWT authentication, multilingual interface, cloud deployment, FastAPI, React.

\section{Актуальность темы исследования}

Электронная коммерция является одним из наиболее динамично развивающихся секторов цифровой экономики. По данным Международной организации электронной коммерции, глобальный объём онлайн-торговли ежегодно прирастает на 15--20\%. Казахстан демонстрирует аналогичную тенденцию: по информации Агентства по статистике РК, объём рынка электронной торговли страны превысил 2 триллиона тенге, а число интернет-покупателей ежегодно увеличивается на 25--30\%.

Несмотря на рост рынка, значительная часть отечественных торговых предприятий либо использует зарубежные платформы (Kaspi, AliExpress), либо располагает устаревшими информационными системами, не адаптированными к локальным особенностям: трёхъязычному интерфейсу (казахский, русский, английский), валюте тенге, региональной логистике и системам рассрочки платежей. Проектирование собственной информационной системы позволяет устранить эти недостатки и создать конкурентоспособный продукт.

Разработка полнофункциональной информационной системы электронной торговли с учётом казахстанской специфики представляет как научный интерес с точки зрения системного проектирования, так и практическую значимость для малого и среднего бизнеса страны.

\section{Электронная коммерция: определения и классификация}

Электронная коммерция (e-commerce) определяется как форма торговых отношений, при которой заключение договоров и операционная деятельность осуществляются с использованием информационно-коммуникационных технологий, преимущественно сети Интернет \cite{turban2018}. В научной литературе выделяют несколько классификационных групп:

\begin{itemize}
  \item по типу участников: B2B (бизнес--бизнес), B2C (бизнес--потребитель), C2C (потребитель--потребитель), G2B (государство--бизнес);
  \item по типу товаров: физические товары, цифровые товары, услуги;
  \item по модели доставки: собственная логистика, агрегаторы доставки, цифровая дистрибуция.
\end{itemize}

Разрабатываемая система TechStore относится к модели B2C с поддержкой как физических (гаджеты), так и цифровых товаров (программное обеспечение, курсы, шаблоны).

\section{Обзор существующих платформ}

\subsection{Зарубежные платформы}

\textit{Shopify} --- облачная SaaS-платформа с широкой экосистемой плагинов. Недостатки для казахстанского рынка: отсутствие интегрированной поддержки казахского языка, ограниченные возможности интеграции с местными платёжными системами, высокая стоимость (от \$39/мес.), транзакционные комиссии \cite{shopify2024}.

\textit{WooCommerce} --- расширение WordPress. Гибкость настройки компенсируется высокой сложностью поддержки, уязвимостями безопасности и значительными накладными расходами на обслуживание \cite{woocommerce2024}.

\textit{Magento (Adobe Commerce)} --- энтерпрайз-платформа с широкими возможностями, но чрезвычайно высокими затратами на внедрение и лицензирование, не обоснованными для малого и среднего бизнеса \cite{adobe2024}.

\subsection{Казахстанские платформы}

\textit{Kaspi.kz} --- лидер местного рынка, однако является закрытой экосистемой с обязательной комиссией с продаж (10--20\%), жёсткими требованиями к продавцам и отсутствием возможности создания собственного брендированного магазина \cite{kaspi2024}.

\textit{Satu.kz / Flip.kz} --- платформы-агрегаторы с ограниченными возможностями кастомизации и собственной программы лояльности.

\textbf{Вывод:} ни одна из рассмотренных платформ не обеспечивает полного контроля над продуктом, гибкой программой лояльности, трёхъязычным интерфейсом и интеграцией с региональной логистикой одновременно при низкой стоимости владения.

\section{Технологический стек: обзор литературы}

\textbf{React и компонентный подход.} Библиотека React, разработанная Facebook в 2013 году, реализует концепцию виртуального DOM для эффективного обновления пользовательского интерфейса \cite{react2024}. Компонентный подход обеспечивает повторное использование кода и упрощает тестирование. Исследования Garrett (2022) показывают, что приложения на React демонстрируют на 40\% меньшее время до интерактивности (TTI) по сравнению с традиционными MPA \cite{garrett2022}.

\textbf{FastAPI.} Фреймворк FastAPI, основанный на Python 3.6+ с использованием аннотаций типов, обеспечивает автоматическую генерацию документации OpenAPI/Swagger, валидацию данных через Pydantic и асинхронную обработку запросов. По результатам бенчмарков TechEmpower, FastAPI превосходит Flask в пропускной способности на 300\% \cite{fastapi2024}.

\textbf{PostgreSQL.} Объектно-реляционная СУБД PostgreSQL является стандартом де-факто для транзакционных систем. ACID-совместимость, поддержка JSON-полей, расширенные типы индексов (GiST, GIN, BRIN) делают её оптимальным выбором для e-commerce систем \cite{postgresql2024}.

\textbf{JWT-аутентификация.} Стандарт JSON Web Tokens (RFC 7519) обеспечивает безсостоятельную (stateless) аутентификацию, что критично для горизонтального масштабирования. Использование симметричной подписи (HS256) обеспечивает целостность токена \cite{rfc7519}.

\section{Программы лояльности в электронной коммерции}

Исследования Reichheld \& Schefter (2000) показали, что увеличение удержания клиентов на 5\% повышает прибыль на 25--95\% \cite{reichheld2000}. Современные программы лояльности классифицируются как:

\begin{itemize}
  \item \textbf{Балльные системы} --- начисление баллов за покупки (Amazon Prime, Kaspi Gold);
  \item \textbf{Уровневые системы (Tiered)} --- присвоение статуса в зависимости от суммы покупок (Сбербанк Спасибо, Starbucks Rewards);
  \item \textbf{Кешбэк-системы} --- возврат процента от суммы покупки на счёт;
  \item \textbf{Гибридные системы} --- комбинация уровней и кешбэка.
\end{itemize}

В разрабатываемой системе реализована гибридная модель: статус определяется накопленной суммой покупок, а процент кешбэка зависит от статуса (0\% для начального уровня до 50\% для максимального). Кешбэк начисляется только при оплате банковской картой, что стимулирует безналичные платежи.

\section{Интернационализация (i18n) веб-приложений}

Интернационализация (i18n) и локализация (l10n) являются ключевыми требованиями для продуктов, ориентированных на многоязычные рынки. Казахстан имеет государственный (казахский) и официальный (русский) языки, а деловая среда активно использует английский \cite{stat2023}. В разрабатываемой системе использована библиотека i18next с React-адаптером, обеспечивающая динамическое переключение языка без перезагрузки страницы.

\section{Облачный деплой и DevOps-практики}

Модель развёртывания PaaS (Platform as a Service) на платформах Vercel и Render обеспечивает: автоматизированный CI/CD из GitHub-репозитория, автоматическое масштабирование, встроенный SSL/TLS, мониторинг и логирование. Сравнительный анализ показывает, что время первичного развёртывания на PaaS-платформах составляет минуты против часов при использовании традиционных виртуальных серверов \cite{12factor}.

\section{Архитектурные паттерны веб-приложений}

\subsection{Монолитная vs. Микросервисная архитектура}

Монолитная архитектура предполагает размещение всей бизнес-логики в одном деплоицируемом юните. Преимущества: простота разработки и тестирования, низкая задержка между компонентами. Недостатки: сложность масштабирования отдельных компонентов, риск каскадных отказов.

Микросервисная архитектура декомпозирует приложение на независимо деплоицируемые сервисы. Преимущества: независимое масштабирование, технологическое разнообразие, изоляция отказов. Недостатки: сложность оркестрации, накладные расходы на сетевое взаимодействие.

В данной работе применена \textbf{модульная монолитная архитектура} (Modular Monolith) для бэкенда: единый процесс FastAPI с чёткой модульной декомпозицией роутеров (\texttt{/api/auth}, \texttt{/api/products}, \texttt{/api/orders} и др.). Это обеспечивает простоту деплоя при сохранении логической изоляции модулей и возможности последующей миграции в микросервисы.

\subsection{REST и принципы проектирования API}

REST (Representational State Transfer) --- архитектурный стиль, описанный Роем Филдингом в 2000 году \cite{fielding2000}. HTTP-методы маппируются на CRUD-операции:

\section{Модель аутентификации и безопасности}

\subsection{JWT-аутентификация}

Процесс аутентификации:
\begin{enumerate}
  \item Пользователь отправляет \texttt{POST /api/auth/token} с email и паролем.
  \item Сервер верифицирует пароль через \texttt{bcrypt.checkpw()}.
  \item При успехе генерируется JWT-токен с полезной нагрузкой \texttt{\{sub: email, exp: now+30days\}} и подписывается с помощью HS256 и SECRET\_KEY.
  \item Клиент сохраняет токен в памяти приложения (React Context) и localStorage.
  \item Все защищённые запросы включают заголовок \texttt{Authorization: Bearer <token>}.
\end{enumerate}

\subsection{Верификация электронной почты}

При регистрации генерируется UUID-токен, сохраняется в таблице \texttt{email\_verification\_tokens} и отправляется через Resend API. Токен действителен 24 часа. Неверифицированные пользователи не могут оформлять заказы.

import bcrypt

def hash_password(password: str) -> str:
    return bcrypt.hashpw(
        password.encode(), bcrypt.gensalt(rounds=12)
    ).decode()

def verify_password(password: str, hashed: str) -> bool:
    return bcrypt.checkpw(password.encode(), hashed.encode())
\end{lstlisting}

\begin{lstlisting}[language=Python,caption={Генерация JWT-токена}]
from jose import jwt
from datetime import datetime, timedelta

def create_access_token(data: dict) -> str:
    payload = {
        **data,
        "exp": datetime.utcnow() + timedelta(days=30)
    }
    return jwt.encode(payload, SECRET_KEY, algorithm="HS256")
\end{lstlisting}

@router.get("/products")
def get_products(
    q: str = None,
    category: str = None,
    min_price: float = None,
    max_price: float = None,
    db: Session = Depends(get_db)
):
    query = db.query(Product).filter(Product.is_active == True)
    if q:
        tokens = q.strip().split()
        for token in tokens:
            query = query.filter(
                Product.name.ilike(f"%{token}%") |
                Product.description.ilike(f"%{token}%")
            )
    if category:
        query = query.filter(Product.category == category)
    if min_price:
        query = query.filter(Product.price >= min_price)
    if max_price:
        query = query.filter(Product.price <= max_price)
    return query.all()

\chapter*{ЗАКЛЮЧЕНИЕ}
\addcontentsline{toc}{chapter}{ЗАКЛЮЧЕНИЕ}

В рамках магистерской диссертации разработана и программно реализована многофункциональная информационная система электронной торговли «TechStore», адаптированная к условиям казахстанского рынка.

\textbf{Достигнутые результаты:}
\begin{enumerate}
  \item Проведён сравнительный анализ существующих платформ электронной коммерции, выявлены их ограничения применительно к локальному рынку.
  \item Спроектирована реляционная модель данных на 10 таблицах, охватывающая все аспекты деятельности интернет-магазина.
  \item Реализован REST API (более 60 эндпоинтов) на базе FastAPI с JWT-аутентификацией и ролевым разграничением доступа.
  \item Разработан SPA-фронтенд на React с поддержкой трёх языков и нечётким поиском в реальном времени.
  \item Реализована девятиуровневая гибридная программа лояльности с дифференцированными ставками кешбэка (0\%--50\%).
  \item Создан модуль доставки для 55 городов Казахстана с автоматическим сопоставлением с ближайшим из пяти филиалов.
  \item Система успешно развёрнута в облачной инфраструктуре (Vercel + Render) с автоматическим CI/CD.
  \item Функциональное тестирование подтвердило выполнение всех 24 требований; p95 времени ответа API составил 287 мс.
  \item Операционные расходы составляют менее 8\,000~тг/мес; окупаемость достигается в течение 1--2 месяцев работы.
\end{enumerate}

\textbf{Направления дальнейшего развития:} интеграция с реальным платёжным шлюзом (Kaspi Pay / Freedom Pay), внедрение рекомендательной системы на основе истории покупок, разработка мобильного приложения (React Native), добавление аналитического модуля с визуализацией данных.
